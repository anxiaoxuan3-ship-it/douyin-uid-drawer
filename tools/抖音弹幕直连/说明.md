# 抖音弹幕直连（实验性）

让抽号器**自动读到你直播间公屏上的弹幕**，不用手动粘贴。

---

## 它是怎么工作的

```
  你自己电脑上的 Chrome / Edge（开着一个抖音直播间网页）
            │
            │  Chrome DevTools 调试协议（本机 127.0.0.1:9222）
            ▼
      douyin_bridge.py
            │  监听网页发出的 WebSocket 二进制帧
            │  解压 gzip → 解 protobuf → 取出「谁说了什么」
            │
            │  HTTP POST /push
            ▼
      抖音UID抽号器   →  识别 UID  →  进参与池  →  抽奖
```

**为什么不直接连抖音的服务器？**
抖音直播间的弹幕通道要求一个叫 `signature` 的签名，它是抖音自己那段混淆
JavaScript 算出来的，而且还有设备/IP 风控。自己模拟很容易被挡（实测会被返回
`DEVICE_BLOCKED`）。借一个**真实的浏览器**去开直播间，签名和设备指纹都由浏览器
自己搞定，我们只是在旁边"听"它收到的数据 —— 这条路实测可用。

> 也试过**自己算签名直连**抖音的 WebSocket。签名算法本身能跑通，但会被抖音的
> 设备/IP 风控前置挡掉（返回 `DEVICE_BLOCKED`），换域名、补 cookie 都一样。
> 所以**唯一的方案就是浏览器抓帧**，那条死路已经删掉了。

## 怎么用

### 1. 先启动抽号器

启动「抖音UID抽号器」，切到 **弹幕来源** 页，确认 **① HTTP 推送** 已经勾上、
状态显示「已启动」。

### 2. 拿到你的直播间号

直播时用浏览器打开你自己的直播间，地址栏里那串数字就是：

```
https://live.douyin.com/123456789
                          ^^^^^^^^^
```

### 3. 启动桥接

**推荐**：在抽号器「弹幕来源 → ⑥ 抖音弹幕直连」里填好直播间号，
点「**直接启动桥接**」。

**或者**双击本目录的 `启动抖音直连.bat`（不带参数的话它会随便找个公开房间）。

它会：
1. 打开一个**独立的** Chrome/Edge 窗口（专用配置目录，不影响你平时的浏览器）；
2. 进入你指定的直播间；
3. 开始把弹幕转发给抽号器。

抽号器的 **日志** 页会立刻开始滚动，来源显示「抖音直连」。

命令行用法：

```
python douyin_bridge.py 你的直播间号
```

也可以直接传完整网址。其它常用参数：

| 参数 | 作用 |
|---|---|
| `--push-to http://127.0.0.1:8787` | 抽号器地址（默认会自动从抽号器配置里读） |
| `--token xxx` | 抽号器设了 token 时用 |
| `--rotate-after 60` | 没指定房间号时，多少秒没弹幕就自动换房间（默认 60） |
| `--no-auto-rotate` | 关掉自动换房间 |
| `--port 9222` | 浏览器调试端口 |
| `--profile D:\某目录` | 换一个浏览器配置目录（排查用） |
| `--attach` | 不启动浏览器，直接连已经在跑调试端口的浏览器 |

### 关于 Python

桥接脚本需要一个 Python。本目录的 `..\python\` 里**带了一个便携版**，
所以正常情况下**什么都不用装**。

启动时会优先用系统里装的 Python（兼容性最好），找不到才用随包的便携版。
用的哪个会打印在窗口第一行。

## 会不会被抖音风控？

分**技术特征**和**平台规则**两层说，两件事不能混为一谈。

### 一、技术特征（实测，不是猜的）

**`navigator.webdriver` 始终是 `false`。**

这是网页识别自动化最常用、也最有效的信号。Chrome 只有在带 `--enable-automation`
启动时才会把它置为 `true` —— 那是 Selenium / ChromeDriver 的做法。实测四种情况：

| 启动方式 | `navigator.webdriver` |
|---|---|
| 普通浏览器（对照） | `false` |
| 带 `--remote-debugging-port`，没挂 CDP | `false` |
| **挂了 CDP（桥接的做法）** | **`false`** |
| 挂了 CDP + 关掉 AutomationControlled | `false` |

> 复现方法：把 `navigator.webdriver` 写到 `document.title` 上，
> 然后用 Win32 读窗口标题（这个读法本身不经过 CDP，不会干扰实验）。

**桥接对抖音只读不写。** 整个脚本只用了 3 个 CDP 命令：

```
Network.enable      —— 打开网络事件监听
Page.enable         —— 打开页面事件监听
Page.navigate       —— 打开/切换直播间页面
```

没有 `Runtime.evaluate`、没有按键/输入注入、没有伪造请求、没有自己去算签名。
弹幕的心跳和 ack 是**抖音自己的页面 JS** 发的，桥接只是在旁边听。

浏览器、UA、TLS 指纹都是真实 Chrome；独立配置目录，**默认没有登录任何账号**。

### 二、行为特征（这才是真正要留意的地方）

| 用法 | 页面加载频率 | 像不像人 |
|---|---|---|
| **填自己的直播间号** | 只打开 1 次，之后纯被动收帧 | 很像（就是"挂着看直播"） |
| 不填房间号、自动轮换 | 每 15~60 秒换一个房间 | 不太像，更像爬虫 |
| 长时间挂着不关 | 一个从无人工输入的会话持续几小时 | 一般 |

### 三、平台规则

抖音的用户协议原则上不允许「自动化访问 / 批量获取数据」。
**所以即便技术上没被识别出来，这件事本身仍然算灰色地带。**
这一点我必须说清楚 —— 测出"没有自动化特征"不等于"平台允许"。

### 四、实测观察

我在这台机器上跑过十几次完整流程：

- 弹幕 WebSocket 握手成功了很多次，也抓到了真实弹幕（`果宇蔬菜购销中心: 吊伙没干` 这种）
- 页面一直正常加载 —— 主播昵称、礼物栏、视频元素都在，**没见过验证码或登录墙**
- 分类页抓取（找房间号用）每次都正常返回
- 但**用纯 Python 自己算签名直连**抖音服务器那条路，会被前置风控直接返回
  `DEVICE_BLOCKED`（跟签名对不对无关）。这也是为什么现在只剩浏览器抓帧这一条路

### 五、把风险压到最低的做法

1. **填自己的直播间号**。这是最有效的一条 —— 只加载一次页面，之后纯被动，
   和不填房间号、疯狂换房间完全不是一个量级。
2. **不要在那个桥接浏览器里登录你的大号**。看公开直播间的弹幕不需要登录。
   万一非要登录，用小号。
3. **不用的时候把桥接关掉**。程序现在默认在退出时把它启动的浏览器一起关掉
   （想留着就加 `--keep-browser`）。
4. **别 24 小时挂着**。
5. 程序默认已经加了 `--disable-blink-features=AutomationControlled`，
   把 `AutomationControlled` 这个 Blink 特性关掉，去掉其它可能的自动化特征。

## 常见问题

**Q：窗口一闪就没了 / 提示没找到 python**
本脚本需要 Python。如果用打包好的 exe 版抽号器，这里仍然要装一个 Python
（<https://www.python.org/downloads/>，安装时勾选 *Add python.exe to PATH*）。

**Q：日志里一直没有弹幕**
1. 确认那个直播间真的有人在说话（自己发一条试试）；
2. 用 `python douyin_bridge.py 你的房间号` 指定自己的房间；
3. 桥接的窗口里如果抖音弹了验证码/登录框，手动点掉；
4. 看看桥接的黑色窗口里有没有 `发现弹幕通道：wss://webcast...` 这行 ——
   有就说明已经接上了，只是那个房间没人说话。

**Q：抽号器那边显示「推给抽号器失败」**
抽号器没启动，或者 **弹幕来源** 页里的 **① HTTP 推送** 没勾上，
或者端口不是 8787（那就用 `--push-to` 指定）。

**Q：会不会影响我平时用的浏览器？**
不会。桥接用的是独立配置目录（默认 `C:\Users\你的用户名\.douyin_bridge_profile`），
跟你日常的 Chrome 完全隔离。第一次打开会是一个"全新浏览器"，什么登录状态都没有
—— 看公开直播间的弹幕不需要登录。

**Q：会被抖音封号吗？**
桥接不登录、不发言，只是被动接收一个公开页面的公开数据。风险很低，但这类
"读取直播数据"的行为本身处在平台规则的灰色地带，请自行判断。**建议用小号/干净
的浏览器配置**。

**Q：抖音改版了怎么办？**
这个方案不依赖签名算法，只依赖 protobuf 的字段号。字段号很少变。
真变了的话，改 `douyin_pb.py` 里的字段号即可（文件顶部注释写了每个字段的含义）。

## 文件说明

| 文件 | 作用 |
|---|---|
| `启动抖音直连.bat` | 一键启动 |
| `douyin_bridge.py` | 主程序：CDP 抓帧 + 解析 + 转发 |
| `douyin_pb.py` | 手写的 protobuf 解析器（不需要 protoc）。可单独运行做自检 |
| `wsclient.py` | 极简 WebSocket 客户端（纯标准库） |
| `..\python\` | 随包分发的便携 Python（没装 Python 时的兜底） |
| `浏览器配置\` | 首次运行时自动生成的浏览器数据，删掉即可重置（不影响你的日常浏览器） |

自检一下解析器是否正常：

```
python douyin_pb.py
```

应输出 `=> 全部通过`。
